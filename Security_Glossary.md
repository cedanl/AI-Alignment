**AI Security Glossary**

Alphabetical glossary of AI security terminology based on a three-domain lens (Defensive Robustness / AppSec / Agentic Capability).

| **Term** | **Definition** | **Source** |
|------------------------|------------------------|------------------------|
| **Adversarial example** | An input deliberately modified to cause a model to make an error, e.g., an image or prompt perturbed so slightly that humans notice no change but the model misclassifies it. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Adversarial machine learning (AML)** | The field studying attacks on ML systems (evasion, poisoning, privacy breaches, model abuse) and corresponding mitigations across the ML lifecycle. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Adversarial suffix** | A seemingly meaningless string of characters appended to a prompt that reliably causes an LLM to bypass its safety measures; often optimized automatically and transferable across models. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html), [arXiv:2307.15043](https://arxiv.org/abs/2307.15043)] |
| **Agentic AI** | LLM-based systems augmented with planning, tool use, memory, and peer-agent protocols (e.g., MCP, A2A) that act autonomously over multi-step tasks; their attack surface differs materially from standalone model inference. | [[arXiv:2603.11088](https://arxiv.org/abs/2603.11088)] |
| **Agentic tool/function calling** | The mechanism by which an agent invokes external tools, APIs, and plugins; each tool invocation extends the attack surface beyond the prompt interface. | [[arXiv:2604.23338](https://arxiv.org/abs/2604.23338)] |
| **AI red teaming** | Adversarial testing that treats the model as an untrusted user to probe trust boundaries and access controls; ATLAS catalogs real-world case studies of such attacks. | [[MITRE ATLAS](https://atlas.mitre.org/)] |
| **Alignment** | Training an LLM to follow safety protocols and refuse harmful requests; "over-assistance" and misalignment create the conditions for jailbreaking. | [[arXiv:2407.04295](https://arxiv.org/abs/2407.04295)] |
| **Backdoor (trojan) attack** | A poisoning attack that implants hidden behavior triggered only by a specific attacker-chosen input, leaving the model's normal performance intact. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Capture The Flag (CTF) benchmarking** | Evaluating agent autonomy by scoring whether AI agents can autonomously solve realistic offensive-security challenges (e.g., Cybench). | [[arXiv:2408.08926](https://arxiv.org/abs/2408.08926)] |
| **ClickFix** | A social-engineering lure where a fake web page (e.g., a fake CAPTCHA or "verify you're human" prompt) quietly places a command on the user's clipboard and talks them through pasting it into a terminal — a top initial-access method; variants like TerminalFix direct users to PowerShell. | [[The Hacker News](https://thehackernews.com/2026/09/threat-actors-dont-want-better-attacks.html), [BleepingComputer](https://www.bleepingcomputer.com/news/security/microsoft-warns-of-terminalfix-attacks-deploying-reverse-tunnels/)] |
| **CWE / CVE mapping** | Classifying vulnerabilities (in code an LLM generates, or in AI systems themselves) against the Common Weakness Enumeration taxonomy and CVE databases; repository-level benchmarks test whether generated code introduces CWEs. | [[A.S.E, arXiv:2508.18106](https://arxiv.org/html/2508.18106v2)] |
| **Cryptographic Context Injection** | An attack that encrypts or obfuscates malicious instructions so the LLM processes them but content filters cannot, causing the model to exfiltrate user data; demonstrated against Grok and Microsoft 365 Copilot. | [[Ars Technica](https://arstechnica.com/security/2026/08/grok-exfiltrates-user-data-when-malicious-instructions-are-encrypted/)] |
| **Data poisoning** | Corrupting training or fine-tuning data so the model learns backdoored, biased, or degraded behavior; applies to any stage that writes weights, not just pre-training. | [[OWASP LLM05](https://genai-security-project.github.io/crosswalk/llm-top10/), [NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Direct prompt injection** | A user's prompt input directly alters model behavior in unintended ways — either maliciously crafted or unintentional; cataloged as ATLAS technique AML.T0051.000. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html), [MITRE ATLAS](https://atlas.mitre.org/techniques/AML.T0051.000)] |
| **Evasion attack** | An adversary crafts inputs at inference time to make a model produce attacker-chosen outputs without altering the model itself. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **EU AI Act** | The EU's risk-based regulation (Regulation (EU) 2024/1689) for AI systems, including obligations for general-purpose AI (GPAI) model providers. | [[EU AI Act Explorer](https://artificialintelligenceact.eu/ai-act-explorer/)] |
| **Excessive agency** | LLM features with tool/API access taking autonomous, real-world actions without appropriate scope limits, human oversight, or reversibility controls. | [[OWASP LLM03](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Guardrails (input/output filtering)** | Application-layer controls — semantic filters, format validation, string checks, privilege restriction — that constrain what reaches the model and what it may return; mitigations, not fool-proof prevention. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html)] |
| **Hallucination / misinformation** | LLMs generating confident, plausible but factually incorrect output (fabricated citations, outdated facts) that users or downstream systems act on as true. | [[OWASP LLM07](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Hidden context exposure / system prompt leakage** | Extraction, inference, or reconstruction of non-user-facing context — system prompts, developer instructions, tool schemas — handing attackers credentials and control logic. | [[OWASP LLM08](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Improper output handling** | Passing unsanitized LLM output to downstream systems (interpreters, browsers, SQL engines), enabling XSS, code injection, SSRF, or privilege escalation. | [[OWASP LLM10](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Indirect prompt injection** | Injection via external content the LLM ingests (webpages, files, retrieved documents, tool outputs) rather than direct user input; cataloged as ATLAS technique AML.T0051.001. | [[arXiv:2302.12173](https://arxiv.org/pdf/2302.12173.pdf), [MITRE ATLAS](https://atlas.mitre.org/techniques/AML.T0051.001)] |
| **Insecure code generation** | LLMs producing code containing exploitable vulnerabilities (CVEs/CWEs); repository-level benchmarks test multi-file generation for introduced weaknesses. | [[A.S.E, arXiv:2508.18106](https://arxiv.org/html/2508.18106v2)] |
| **Jailbreak** | A form of prompt injection where inputs cause the model to disregard its safety protocols entirely; effective prevention requires ongoing updates to training and safety mechanisms, not just system-prompt safeguards. Cataloged as ATLAS AML.T0054. | [[arXiv:2407.04295](https://arxiv.org/abs/2407.04295), [OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html), [MITRE ATLAS](https://atlas.mitre.org/techniques/AML.T0054)] |
| **Known Exploited Vulnerabilities (KEV) Catalog** | CISA's authoritative catalog of CVEs with evidence of active exploitation; used to prioritize remediation and a key signal for mapping news events to real-world attack activity. | [[CISA](https://www.cisa.gov/cybersecurity-advisories/all.xml)] |
| **llms.txt poisoning** | Planting references to unregistered code packages or domains in a site's llms.txt/llms-full.txt files (an emerging convention for AI-readable site summaries), so visiting AI agents automatically install attacker-controlled code. | [[Ars Technica](https://arstechnica.com/security/2026/08/claude-codex-and-hermes-installed-unowned-code-inside-corporate-networks/)] |
| **Membership inference** | Determining whether a specific data point was in a model's training set — a privacy attack that differential privacy is intended to mitigate. | [[arXiv:2202.12232](https://arxiv.org/abs/2202.12232)] |
| **MITRE ATLAS** | A living knowledge base of adversary tactics and techniques against AI-enabled systems (ATT&CK-style), including prompt injection and jailbreak techniques with real-world case studies. | [[MITRE ATLAS](https://atlas.mitre.org/)] |
| **Model extraction (stealing)** | Recreating a model's functionality by training a substitute on its outputs — an IP and privacy attack included in NIST's AML taxonomy. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Model inversion** | Recovering sensitive features of training data from model outputs, another privacy breach class in the NIST AML taxonomy. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Multimodal injection** | Hiding instructions in non-text modalities (images, audio, video) that accompany benign text, so cross-modal processing triggers hidden prompts. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html)] |
| **NIST AI RMF** | The voluntary U.S. framework (AI RMF 1.0, with a Generative AI Profile) for managing AI risks across the lifecycle, organized around Govern/Map/Measure/Manage. | [[NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)] |
| **OWASP LLM Top 10** | The OWASP GenAI Security Project's risk taxonomy for LLM applications, from prompt injection (LLM01) to improper output handling (LLM10); the LLM-Top10-2025/2026 editions map each risk to mitigations and frameworks. | [[OWASP LLM Top 10](https://owasp.org/www-project-top-10-for-large-language-model-applications/assets/PDF/OWASP-Top-10-for-LLMs-v2025.pdf)] |
| **Payload splitting** | Splitting a malicious prompt into fragments (e.g., across a document) that are individually benign but combine into an attack when the model processes them together. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html)] |
| **Prompt injection** | Untrusted input altering an LLM's behavior or output in unintended ways — inputs need not be human-readable, only parsed by the model; RAG and fine-tuning do not fully mitigate it. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html)] |
| **Reward hacking** | Agents over-optimizing for a benchmark or evaluation reward — pursuing "winning" beyond the intended task, up to unauthorized actions; drove OpenAI agents to conscript each other via an improvised message board and breach Hugging Face during security evaluations. | [[The Hacker News](https://thehackernews.com/2026/08/openai-says-reward-hacking-drove-ai.html), [Ars Technica](https://arstechnica.com/security/2026/08/how-openai-let-a-mob-of-llm-agents-game-a-test-and-ransack-hugging-face/)] |
| **Retrieval-Augmented Generation (RAG)** | Grounding LLM outputs in retrieved external documents; improves relevance but adds an indirect-injection channel through the retrieved content. | [[OWASP LLM01](https://owasp.org/www-project-top-10-for-large-language-model-applications/2_0_vulns/LLM01_PromptInjection.html)] |
| **Secure code generation** | Methods (instruction tuning, constrained decoding, RAG with security knowledge) aiming to make LLM-generated code correct and free of vulnerabilities; evaluation schemes remain contested. | [[arXiv:2503.15554](https://arxiv.org/abs/2503.15554)] |
| **Sensitive information disclosure** | Models surfacing PII, credentials, trade secrets, or private training data through memorization, over-retrieval, or insufficient output filtering. | [[OWASP LLM02](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Session hijacking (AI accounts)** | Infostealer malware stealing active login sessions for AI services, letting attackers access accounts and consume usage (e.g., Claude session theft) — AI accounts are now a first-class credential target. | [[BleepingComputer](https://www.bleepingcomputer.com/news/artificial-intelligence/anthropic-warns-infostealer-malware-is-hijacking-claude-sessions-to-drain-usage/)] |
| **Supply chain (AI)** | Compromise of third-party model components — providers, fine-tuning services, plugins, model hubs — including unsigned weights and hijacked conversion services. | [[OWASP LLM04](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Threat model** | The characterization of attacker goals, capabilities, and knowledge (e.g., black-box vs. white-box access to the learning process) used to structure analysis of AI attacks. | [[NIST AI 100-2](https://csrc.nist.gov/pubs/ai/100/2/e2023/final)] |
| **Unbounded consumption** | Lack of resource limits enabling denial of service/wallet via token flooding, context exhaustion, reasoning loops, or excessive API calls. | [[OWASP LLM06](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Vector/embedding weaknesses** | Vulnerabilities of RAG embedding stores — cross-tenant leakage, semantic injection, direct database access, integrity attacks on stored vectors. | [[OWASP LLM09](https://genai-security-project.github.io/crosswalk/llm-top10/)] |
| **Zero-day** | A vulnerability exploited in the wild before a patch exists (e.g., the PaperCut NG/MF zero-days); the window between first exploitation and patch drives much of the news cycle CISA's KEV catalog tracks. | [[BleepingComputer](https://www.bleepingcomputer.com/news/security/recently-patched-papercut-zero-days-used-in-data-theft-attacks/), [CISA](https://www.cisa.gov/cybersecurity-advisories/all.xml)] |
